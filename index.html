/ 04 · Process

How work gets done

A working pattern from enterprise delivery, not a claim about any one client: understand, design, build, make it accessible, test, and ship with support.

Step 1

Understand

Requirements, user journeys and existing systems first — especially when modernising a legacy application.

requirements · journeys · legacy review

Step 2

Design

Layered APIs, data shapes and reusable components, agreed as tokens and contracts before the build grows.

architecture · tokens · contracts

Step 3

Build

Clean, reviewed code in small increments, with pair and mob programming and code review where the team uses them.

clean code · reviews · increments

Step 4

Make it accessible

Semantic HTML, real labels, keyboard and focus behaviour from the start, then axe-core checks and manual testing.

semantics · keyboard · axe-core

Step 5

Test

Unit and API tests for the rules that matter, performance checks, and validation-failure cases — not only the happy path.

xUnit · API tests · failure cases

Step 6

Ship & support

CI/CD pipelines, repeatable deployments, logging and troubleshooting in production, and maintenance after launch.

pipelines · logging · maintenance
